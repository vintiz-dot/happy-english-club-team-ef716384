# A2.1 - Teacher stability: diagnosis and pin

Where I am / next step: all scenarios work at 1024x768 and first verdicts are below. Full baseline run at all three sizes started (results -> docs/evidence/A2.1/results.json). Next: fill the results table from it, then the briefs.

## How to run

```
node scripts/a11y-teacher/teacher-stability.mjs --harness C:\Users\Dell\hec-tools\a2-harness --port 5321 [--idle-minute] [--only flipbook,overlays,hints,targets,hud,static] [--sizes 1024x768,768x1024,375x812] [--out docs/evidence/A2.1]
```

- `--harness`: a folder outside the repo with `node_modules/playwright` (copied from the A0 harness; no repo dependency added). The script copies `scripts/a11y-teacher/preview/` into `<harness>/preview`, links `<harness>/preview/node_modules` to the repo's packages (junction), and starts the repo's own Vite in-process with `@/integrations/supabase/client` aliased to the FAKE client (made-up children; never the live project).
- `/__lab` (preview/lab.tsx) mounts the real LiveEngagementHUD (inside a React Profiler), SkillButton, RadialSkillMenu, StudentActionPopover and one of each ui overlay inside a fullscreen-able element. Every other path is the real App.
- The book is `preview/book.html`, a local 60-page stand-in on a second origin (localhost vs 127.0.0.1) that pushes one history entry per turn and posts `load`/`page` to the parent. **The real providers' in-iframe behaviour (Google Slides, Canva, flipbook hosts) is NOT measured.**
- Auth events: `window.__fakeAuth.emit('TOKEN_REFRESHED')`; tab visibility is simulated by overriding `document.visibilityState` and dispatching `visibilitychange`, on which the fake emits SIGNED_IN with a new session object, as auth-js does (`GoTrueClient.js:2163-2186` -> `:1859`). Realtime: `window.__rt.emit(table, payload)` honours `col=eq.val` filters.
- CPU 4x and a Fast-3G-like profile (CDP) are applied after the app shell has loaded (Vite dev serves hundreds of modules; throttling that would only measure the dev server), plus 562 ms on every book.html request. Touch contexts emulate `hover: none` / `pointer: coarse`.
- One line per check; `FAIL` lines are the gated defects; exit code 1 while any FAIL remains.

No source file under src/ is changed by this task.

## Verdicts so far (first run, 1024x768, CPU 4x, Fast-3G-like network; full table follows after the full run)

- H1 CONFIRMED. TOKEN_REFRESHED: +1 iframe load, book page 51 -> 1, selected book B -> A (booksData[0]), fullscreen DIV -> none. Tab hidden -> visible (fake emits SIGNED_IN with a new session object, as auth-js GoTrueClient.js:2163-2186 -> :1859 does): +1 load, page 11 -> 1, book B -> A.
- H2 CONFIRMED. Presenter -> Settings -> Presenter: +1 load, page 11 -> 1.
- H3 REFUTED as a separate cause: the title-only edit path costs the same +1 as the bare tab round trip, so the edit itself adds 0 loads (its reload is H2's). URL edit: +1 (legitimate).
- H4 CONFIRMED: 50 turns pushed entries into the TAB history (history.length 3 -> 50; Chrome caps it at 50); browser Back moves the book 6 -> 5 and leaves the app URL unchanged.

- H5 CONFIRMED (lab, 1024x768, fullscreen on `#fs-host`; each overlay visible in a non-fullscreen control first): ui/popover, SkillButton popover, StudentActionPopover, ui/dialog, ui/dropdown-menu are portalled to body and NOT visible. ui/sheet visible. On the real TeacherBooks page the classroom-tools sheet IS visible in fullscreen.
- H8 CONFIRMED, in a different shape than the plan says: ui/select and ui/tooltip, the two "fullscreen-aware" primitives, were ALSO portalled to body and invisible in fullscreen. Cause (by reading, consistent with the numbers): the wrapper reads `document.fullscreenElement` only when the WRAPPER renders (`tooltip.tsx:43-44`, `select.tsx:69`); opening an overlay re-renders Radix's own content via context, not our wrapper element, so the value from the last parent render (before fullscreen) is used. The Sheet worked because `LabSheet` / `ClassroomToolsLauncher` own the `open` state and re-render on open. A tooltip open when fullscreen begins stays outside (invisible); one open in fullscreen and still open after exit is visible again (no detached node seen).
- H6 CONFIRMED at 1024x768: ui/tooltip primitive opens on hover and keyboard (23 Tabs) but NOT on tap. Native title= hints (HUD chip "Last engaged", TeacherBooks back / open-in-tab) show no hint on keyboard focus or tap (the HUD chip IS keyboard-reachable, 3 Tabs; a tap opens its StudentActionPopover, which does not show "last engaged").
- H7 CONFIRMED: Live button disabled, pointer-events none; reason tooltip not shown on hover, tap, and the button is NOT reachable with Tab.
- H9 SPLIT: re-render churn REFUTED - 0 HUD commits per unrelated attendance event (React Profiler), because react-query keeps `data` referentially equal when the refetched rows are equal and the HUD reads only `data`. Refetch churn CONFIRMED - the attendance subscription has NO filter, every unrelated event costs 4 HUD queries (enrollments, point_transactions, sessions, attendance), a burst of 5 costs 20. An open StudentActionPopover keeps open and keeps focus across such a refetch.
- H10 PARTLY REFUTED: `index.css:805-812` gives every button and link min 44x44 under `@media (hover: none)`. Touch media (hover none, pointer coarse; emulated by CDP): HUD chips 0 of 6 under 44, RadialSkillMenu 0 of 19, SkillButton popover 1 of 7 (the custom-points INPUT, 48x40 - inputs are not covered by the rule). Mouse media: HUD chips 6 of 6 at 26 px tall, SkillButton point buttons 40x40, RadialSkillMenu 7 of 19 (Back 32 px, correction reasons 34 px), StudentActionPopover attendance buttons 32 px. So on a tablet the plan's numbers do not apply; on a hover-capable touch screen (e.g. a Windows touch panel reporting hover) they would - not verified here.
- H8 (second run, probe for split text fixed): ui/select inside the real TeacherBooks classroom-tools sheet IS inside fullscreen and hit-testable; in the lab the same primitive is outside. Consistent with the stale-read cause: the TeamMaker Select mounts (Deferred) after fullscreen began.

## Where the code differs from the plan's reading (re-read at this merge)

- TeacherBooks "Open directly in tab" title= is at `TeacherBooks.tsx:515`, not :518.
- `useAuth.tsx:66-71`: every non-SIGNED_OUT auth event ALSO re-fetches the role (`fetchRole`, one `user_roles` request) and re-sets state; TOKEN_REFRESHED is not special-cased at all (:52-58 only returns for SIGNED_OUT).
- H5 is narrower than "Select/Dialog/Sheet to be checked": `ui/select.tsx:69` and `ui/sheet.tsx:58-61` ALREADY portal into `document.fullscreenElement` (read at render, like tooltip). Not fullscreen-aware: `ui/popover.tsx:14`, `ui/dialog.tsx:34`, `ui/dropdown-menu.tsx:59`, `ui/alert-dialog.tsx:32`.
- HUD realtime effect is `LiveEngagementHUD.tsx:113-131`; the unfiltered attendance subscription is :122-126.
- More native title= hints exist than H6 lists: `TeacherTranscripts.tsx:825, 912, 1439, 1449` and `TeacherSmartUpload.tsx:969, 1010` as well. The script gates the ones the plan listed.
- Classroom tools: only `LeaderboardTool.tsx:27` and `TeamMaker.tsx:31` import an overlay primitive, and it is `ui/select` (fullscreen-aware). No tool panel imports popover/dialog directly.
