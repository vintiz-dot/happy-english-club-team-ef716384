## How to run

```
node scripts/a11y-teacher/teacher-stability.mjs --harness C:\Users\Dell\hec-tools\a2-harness --port 5321 [--idle-minute] [--only static,flipbook,overlays,hints,targets,hud] [--sizes 1024x768,768x1024,375x812] [--out docs/evidence/A2.1]
```

About 30 minutes for the full run (CPU 4x). Use `--only` and `--sizes` for a quick loop; the gate is the full run.

- `--harness`: a folder outside the repo with `node_modules/playwright` (copied from the A0 harness; no repo dependency added; Chrome via Playwright's `chrome` channel, nothing downloaded). The script copies `scripts/a11y-teacher/preview/` into `<harness>/preview`, links `<harness>/preview/node_modules` to the repo's packages (junction), and starts the repo's own Vite IN-PROCESS (so there is no separate server to stop) with `@/integrations/supabase/client` aliased to the FAKE client (made-up children; never the live project).
- `/__lab` (`preview/lab.tsx`) mounts the real LiveEngagementHUD (inside a React Profiler, the plan's "test-only wrapper"), SkillButton, RadialSkillMenu, StudentActionPopover and one of each ui overlay inside a fullscreen-able element, with App.tsx's providers and QueryClient defaults. Every other path is the real App.
- The book is `preview/book.html`, a local 60-page stand-in on a second origin (localhost vs 127.0.0.1) that pushes one history entry per turn and posts `load` / `page` to the parent. **The real providers' in-iframe behaviour (Google Slides, Canva, flipbook hosts) is NOT measured.**
- Auth: `window.__fakeAuth.emit('TOKEN_REFRESHED')` delivers a NEW session object, as auth-js does (`node_modules/@supabase/auth-js/dist/module/GoTrueClient.js:1884-1890`). Tab visibility is simulated by overriding `document.visibilityState` and dispatching `visibilitychange`; the fake then emits SIGNED_IN with a new session object, as auth-js does (`GoTrueClient.js:2163-2186` -> `_recoverAndRefresh` -> `:1859`). Realtime: `window.__rt.emit(table, payload)` honours `col=eq.val` filters and records every subscription.
- CPU 4x and a Fast-3G-like profile (CDP) are applied after the app shell has loaded (throttling the shell would only measure the Vite dev server), plus 562 ms on every book.html request. Touch contexts emulate `hover: none` / `pointer: coarse` (CDP `Emulation.setEmulatedMedia`).
- One line per check. `FAIL` = gated defect; exit code 1 while any FAIL remains. `INFO` = measured, not gated. `NOTMEASURED` = with reason.

## Verdict per hypothesis

- **H1 CONFIRMED.** M1: TOKEN_REFRESHED and a tab refocus (SIGNED_IN) each reload the book (+1 load), reset it to page 1 and snap the selection back to `booksData[0]` (`TeacherBooks.tsx:199-201`); M2: fullscreen drops. All three sizes. Mechanism as the plan read it: `useAuth.tsx:60-64` new `user` object -> effect deps `[user, toast]` (`TeacherBooks.tsx:227`) -> `setLoading(true)` (:176) -> spinner tree (:411-422) unmounts the iframe and the fullscreen element. Plan assumption 7.1 holds for the installed auth-js (read in its source, emulated by the fake; not observed against a real Supabase session).
- **H2 CONFIRMED.** M3: +1 load and page reset on Presenter -> Settings -> Presenter.
- **H3 REFUTED** as its own cause. The title edit adds 0 loads; the reload seen on that path is H2's tab round trip.
- **H4 CONFIRMED** (the book's turns fill the tab's history; Back walks the book, not the app; after a reload the old entries are stale - Back does nothing visible). Cross-origin, partly unfixable; reported, not gated. Removing H1/H2 reloads removes the "stale" half.
- **H5 CONFIRMED** for popover, dialog, dropdown-menu (and the two teacher popovers built on ui/popover). Not observed on the real TeacherBooks page for the sheet or its Select.
- **H6 CONFIRMED.** Radix tooltip: no tap. Native title=: no tap, no keyboard hint.
- **H7 CONFIRMED.** Not on hover, tap or keyboard.
- **H8 CONFIRMED, broader than the plan.** The "fullscreen-aware" wrappers (`tooltip.tsx:43-44`, `select.tsx:69`, and `sheet.tsx:58-61` the same way) read `document.fullscreenElement` only when the WRAPPER renders. Opening an overlay re-renders Radix's internals via context, not our wrapper element, so a value from before fullscreen is used: ui/select and ui/tooltip were invisible in the lab. They work on the real TeacherBooks page only because `setIsFullscreen` (:232) re-renders the page subtree, or the component mounts after fullscreen (TeamMaker is Deferred). No "detached node after exit" was seen.
- **H9 SPLIT.** Re-render churn REFUTED (0 commits per unrelated event; react-query keeps `data` referentially equal when rows are equal, and the HUD reads only `data`). Refetch churn CONFIRMED (4 queries per unrelated attendance write anywhere in the school; 20 for a burst of 5). The open popover is NOT disturbed.
- **H10 PARTLY REFUTED.** On touch media `index.css:805-812` already makes every button/link >= 44x44; the one touch defect is the SkillButton custom-points input (`SkillButton.tsx:95`, `h-10`, 48x40). The plan's sizes are true only under hover-capable media (whether a classroom touch panel reports `hover: hover` was not verified).
- **R1 CONFIRMED by measurement (parent side):** 0 extra loads and a flat heap over 150 turns; the long tasks seen in the parent (0-5 per 50 turns, under 4x CPU) are not attributable to the turns with this stand-in. Host-side cost not measured (stand-in book).
- **R2** not re-measured (read: only fullscreenchange listeners, `TeacherBooks.tsx:230-246`; no resize handler was found).
- **R3:** parent heap flat (15.7 -> 15.8 MiB over 150 turns). The real hosts' memory is NOT MEASURABLE HERE.

- `index.css:805-812` (44 px under `hover: none`) is not in the plan and changes H10.
- More native title= hints than H6 lists: `TeacherTranscripts.tsx:825, 912, 1439, 1449`, `TeacherSmartUpload.tsx:969, 1010`. Gated: only the plan's list.
- TeacherLeaderboards Live button has no accessible name at 375 (`<span className="hidden sm:inline">Live</span>`, :182).
