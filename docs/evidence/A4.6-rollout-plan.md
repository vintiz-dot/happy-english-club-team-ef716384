# A4.6 Design rollout - plan and foundations

**Where I am / next step:** baseline screenshots taken (scratchpad `before/`, 12 screens x 375/1280 x light/dark + 3 boards); boards animate, so the board gate needs the `--freeze` mode (added to the harness). Pure modules committed (`src/lib/ivoryScope.ts`, `src/lib/givenName.ts`, test 33/0), `IvoryScope` + `UserMenu` written but not wired. Running the 1a experiment (attribute forced on `<html>` over un-migrated screens). Next: wire IvoryScope into App, primitives with `useIvory()` class sets, shell, then the plan (Part 2).

Draft decisions so far (to be confirmed by the experiment):
- Scope: `data-hec-theme="ivory"` on `<html>`, set per ROUTE from one registry (`src/lib/ivoryScope.ts`); primitives and shell choose class strings with `useIvory()`, so an un-migrated screen is byte-for-byte today's look and a migrated one is ivory from header to portals.
- Ship unit = an AREA (student, parent, staff), never a single batch.
- Found: `cn()` (tailwind-merge) silently drops `text-hec-body` when a `text-hec-*` colour follows it; needs the hec names registered in `src/lib/utils.ts`.
