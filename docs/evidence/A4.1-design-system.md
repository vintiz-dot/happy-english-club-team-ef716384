- So with the attribute absent: every rule that applied before still applies, with the same declarations, in the same order, and no new rule applies. Computed styles are identical; pixels are identical.

Why the Tailwind config cannot have changed an existing class:

- Tailwind generates a class only when its name occurs in the scanned sources (`src/**/*.{ts,tsx}`). Before this change no source file contained any name the new keys create: a search of `src` for `[a-z]+-hec-` finds only the DOM id `new-hec-class` (not a utility), and `font-serif` / `font-display` occur nowhere as classes. - `fontFamily.serif` is the one new key that shadows a Tailwind default. Preflight reads `fontFamily.sans` and `mono`, not `serif`, and `font-serif` is unused, so nothing is emitted from it; the byte comparison above would show it otherwise.

## 4. Things to look at

1. **The serif stack is not the existing `--font-studio`.** That stack falls through Book Antiqua and Georgia, and on this Windows machine both lack eight of the nine Vietnamese test characters (ễ ả ư ờ ỹ Ạ Ễ ₫ missing, only đ present; Palatino Linotype, Times New Roman, Cambria and Segoe UI have all nine - read from the font files with WPF's `GlyphTypeface.CharacterToGlyphMap`); Iowan Old Style, its first entry, could not be checked. The new `--hec-font-display` lists only families measured or known to carry Vietnamese. `--font-studio` itself is untouched (the boards use it).
2. **Apple devices were not looked at.** `ui-serif` gives New York on iPhone/iPad/Mac Safari; Vietnamese coverage there is expected, not seen. One iPhone and one Android phone should be looked at before the checkpoint is approved.
3. **Portals.** While the attribute sits on an inner root, dialogs and popovers opened from that screen need the attribute on their own content element.
4. **The boards when the attribute moves to `<html>`.** The bridge would re-point `--background`, `--primary`, `--border` under them. They must be kept out of the scope at that step; see DESIGN_SYSTEM section 17.
5. `hec-line` (the hairline) is decoration and is deliberately not in the contrast table; anything that marks a control uses `hec-line-strong`.
6. Brass and the warning amber are neighbours on the wheel (hue 40 against 29). They are kept apart by job (brass never states a condition, a warning always has an icon and a word) rather than by hue alone.

### The bubble that covers the child's name

Cause (read from the source, and visible in `docs/evidence/A0/student-dashboard-375-light.png` and `-dark.png`): `MascotCompanion.tsx:92` draws the bubble as `absolute left-full bottom-0 ml-3 z-50 max-w-[200px]`, that is, to the right of the 64 px mascot and above everything. `HeroCommandDeck.tsx:91-100` puts the greeting and the name in exactly that place, the next flex child. At 375 the bubble is 200 px wide and lies over both.

Fix: the bubble leaves the absolute layer and becomes a row in the normal flow, so it cannot overlap anything at any width.

1. In `HeroCommandDeck`, the identity block becomes a column: row 1 = mascot + (greeting, name, level chip); row 2 = the message, full width of the card, `mt-3`.
2. The message is rendered there, not inside the mascot. Move the message choice out of `MascotCompanion` into a small hook used by `HeroCommandDeck` (the same inputs: name, streak, pending homework, level), and pass the text down; no data or query changes.
3. Its classes: `rounded-hec-md border border-hec-line bg-hec-raised px-4 py-3 text-hec-body text-hec-ink shadow-hec-1`, with `role="status"`. No tail, or a small one on the top-left edge pointing up at the mascot.
4. Do not hide it after 8 seconds: an in-flow element that disappears moves the page under the child's finger. It stays as the quiet line under the name (and can replace "Rest up for tomorrow's quests!", which says the same thing). If hiding is kept, fade opacity only and keep its space.
5. Check: with the fixture name `Nguyễn Hoàng Phương Thảo Nguyên` at 375 and at 320, the bounding boxes of the name and of the message do not intersect, the name's `scrollWidth` equals its `clientWidth`, and the page has no horizontal scroll.
