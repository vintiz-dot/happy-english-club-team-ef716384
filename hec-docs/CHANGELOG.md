# Changelog

All notable changes to HEC Docs: the engine, and each template with its own semver. A template's version is its schema's `$id` (`https://hec-docs.invalid/schemas/<type>/<version>`).
- **Major:** breaking data contract.
- **Minor:** new variant or optional field.
- **Patch:** visual change with the same data.

## Engine 1.0.0 (2026-11-13)

First release. HTML + CSS Paged Media → headless Chromium (Playwright 1.58.2, build 1208) → tagged PDF. Includes:
- W3C design tokens compiled to CSS variables
- multi-tenant themes
- a Nunjucks component library
- strict JSON Schema validation with field-level errors
- the CLI (`render`, `batch`, `validate`, `list`) and the HTTP API (`/v1/render`, `/v1/batch`, `/v1/templates`, `/healthz`)
- idempotency keys and a concurrency queue
- per-job timeouts and JSON logs
- run manifests
- deterministic output
- quality gates

### Engine notes
- **Deterministic structure IDs.** Chromium names tagged structure elements after DOM node ids, and numbers table header cells in a run-dependent order. Its own ID tree is also run-dependent. The engine renumbers every ID by first appearance in the structure tree and rebuilds the ID tree, so tables keep real `<th scope="col">` headers and output stays byte-identical.
- **Bundled fonts only.** Cormorant Garamond and Be Vietnam Pro, plus Noto Sans Math, Noto Sans Symbols 2 and monochrome Noto Emoji as fallbacks, so pasted arrows and emoji never fall back to a host font.

## What could not be preserved exactly

Content, numbers, dates, currency formatting and filenames are unchanged; `npm run qa` checks every fixture against the original generator's text. The items below are the deliberate or unavoidable differences.

### Every document
- **Brand elements are added:** the header lockup, the running header on pages 2+, the tagline footer, page numbers, and per document an encouragement line, reassurance line, Teacher Victor sign-off and QR to hanoienglish.com. They are registered as brand strings and excluded from parity.
- **The logo is recoloured.** The master (`Logo HEC.pdf`) is pure yellow #FFF200, which is illegible on light paper. Documents use the same vector artwork in navy, with the swoosh in print-safe yellow (`tenants/hec/assets/logo.svg`); the master is kept unchanged beside it. The old raster `public/images/hec_logo.png` is no longer used.
- **Text is real, selectable and tagged** instead of a JPEG screenshot. Copy/paste and screen readers now get the words. Rendering was previously via html2canvas, so nothing a reader saw is lost.

### Homework
- **Filename unchanged, quirk included:** every non-ASCII-alphanumeric character still becomes `_` (e.g. `Unit_6__My_Weekend___B_i_t_p_v__nh__tu_n_2_homework.pdf`). It now has a test.
- **Teacher text is printed through an exact port of the app's `cleanRichHtml`.** Like the app, it drops table structure and a pasted table's header row; the text of the cells runs together as it does on screen. This keeps the content identical to what students see. Improving it is an app change, not a visual one.
- **No anti-AI verification anchors existed** in the original generator, so none were added or changed.
- **The footer line** "Happy English Club • Generated on …" keeps its wording. The date comes from the request's `generatedAt` (default: now), as before.

### Progress report
- Filename unchanged: `<safeFileName(name)> - Progress Report.pdf`. The ZIP name for several students stays the app's.
- **Letterhead line:** "Hanoi English · hanoienglish.com" stays in the header, in place of the tenant subtitle.
- **Name and period line:** the name is now the hero heading and the period sits beside it, with the added label "Reporting period". Words and order are unchanged.
- **Footer:** "Generated by Happy English Club · hanoienglish.com · <date>" is kept. The date prints as the browser's default `en-US` short form (`11/13/2026`), from `generatedAt`.
- **Fixed by the new rendering:** the original drew the score bars through the skill labels, and its print copy dropped the learning-style badges and made the bars invisible. All content now shows.
- **Dropped quirk:** when both `learning_styles` and `recommendations` were empty, React printed a stray "0". It is not reproduced.

### Account statement
- The original was print-only and had no filename. The service names it `<safeFileName(name)> - Account Statement.pdf`.
- Every figure, sign (`+` / `−`) and date is unchanged; the formatters are exact ports (`src/templates/filters/statement.ts`).
- "Hanoi English · hanoienglish.com" moves from the letterhead to the closing colophon.

### Invoice
- **Filenames unchanged, quirk included:** `sanitizeFilename` still turns "Đ" into "_" (`Nguyen__uc_Bao_2026-11.pdf`), and the ZIP is `invoices-<month>-<n>.zip`.
- **Letterhead:** the 1.9 MB background JPG is replaced by the shared header lockup. Its raster slogan ("Growing Confidence, One Word at Atime / Câu lạc bộ Tiếng Anh") was never text; "Câu lạc bộ Tiếng Anh" survives as the tenant subtitle. The organisation name prints separately only when it differs from the tenant name.
- **Fixed by the new rendering:**
  - The single invoice's "Print / Save as PDF" printed a blank page, because a global `@media print` rule hid it.
  - The bulk path squashed each invoice onto one page.
  - Invoices now paginate, with repeating table headers.
- **Prior balance "-0 ₫":** when there is no carry-in the app's adapter yields JavaScript's −0, and the invoice printed "-0 ₫". JSON cannot carry −0, so the template rebuilds it from 0 and the printed text is unchanged.
- **Colour:** the debt row is not red, to avoid pressure cues. Credits and payments use the positive colour. No words changed.
- **No brand QR on the invoice,** so a parent cannot scan the wrong code when paying; the VietQR stays.
- **Data contract:**
  - The VietQR image arrives as a `data:image/png;base64,…` URI (no network at render).
  - `invoice.month` is required (the filename uses it).
  - `bankInfo` may be null; the original fallback sentence prints.
- **Parity baseline:** the single-invoice baseline (`qa/before/invoice-single/dom.txt`) is a text dump of the blank print, so parity runs against the bulk capture of the same component, data and student.

### Access card
- Wording, including the security warning and both Vietnamese lines, is exact.
- The violet chrome becomes ivory and navy.
- The expiry prints as captured (`en-US`, Hanoi time), rather than following whatever the viewer's browser locale is.

### Profile card (PNG)
- **Background:** light ivory replaces the original dark navy card ("light backgrounds only").
- **Icons:** the stat icons, lost in the original capture, are drawn as inline SVG with no text.
- **Avatar:** it must be a data URI or omitted. Without one, decorative initials are drawn (no text added).
